## 1. Data and split

Dataset: `ealvaradob/phishing-dataset` (Hugging Face), revision `23b8c17f4c94`, dated 2023-12-27 (dataset licence at this revision: MIT). This revision contains the train/test files the published model `ealvaradob/bert-finetuned-phishing` was trained and tested on: its `train.json` has 61,849 rows, i.e. 3,866 steps per epoch at batch size 16, matching the model card (3,866; match = True). A later re-upload (`combined_reduced.json`) re-sampled the URLs, so a fresh split of it would have put much of the published model's training data into the test set; it was therefore not used.

The test set is the published `test.json`, unchanged (15,466 rows, which meets the proposal's minimum of 10,000). ## 2. Models and evaluation method

Six models were evaluated by one shared function (`src/evaluate.py`) on the same test set:

- **bert-base, fine-tuned (Kasim)**: bert-base-uncased fine-tuned by us on data/splits/train.parquet
- **bert-large, published model (E. Alvarado) †**: ealvaradob/bert-finetuned-phishing @ fa8fb73a007174c410ab7160d4e4c6e6b8d998d4 (Esteban Alvarado; bert-large-uncased fine-tuned, 336M parameters). Inference only, no training by us.
- **TF-IDF + Logistic Regression**: TF-IDF (1-2 grams, max_df 0.25, English stop words, 50k features; author's settings) + LogisticRegression(max_iter=2000)
- **Random Forest on hand-crafted features**: RandomForest(300 trees) on reference features.py: URLFeatures + TextFeatures for all samples, HTMLFeatures for HTML samples (0 otherwise), plus type flags
- **TF-IDF + XGBoost**: TF-IDF (author's settings) + XGBoost with the author's hyperparameters (colsample_bytree 0.7, gamma 0.2, lr 0.1, max_depth 12, min_child_weight 2, n_estimators 100, subsample 0.8)
- **Regex heuristic (original web app)**: Python port of simulateAnalysis() from frontend/PhishGuard_AI.html; parity with the JS verified by scripts/check_heuristic_parity.py

Fine-tuning of `bert-base-uncased`: learning rate 2e-05, batch size 16, weight decay 0.01, up to 3 epochs, linear schedule, optimiser `adamw_torch_fused`, fp16 = True, seed 42, max length 512 tokens (chosen from training-set token lengths: 79.1% of emails/SMS fit in 512 tokens, only 8.6% of HTML pages). Validation F1 was checked every 1,000 steps; the best checkpoint (step 10437, validation F1 0.9660) was kept. Training took 91 minutes on mps (Apple M4 Pro).

Metrics: accuracy; precision, recall and F1 for the phishing class; false positive rate FPR = FP / (FP + TN); ROC-AUC from the continuous score; mean latency per sample (batched). Decision rule: phishing if score ≥ 0.5 (the heuristic uses its own 'phishing' verdict).

## 4. Explainability and the web system

The backend returns, with each prediction: (1) rule-based indicators, of which 25 rules are defined and 17 can be shown; each is displayed only when it fires, with its evidence, and its 0–100 score is the phishing (or legitimate) rate measured on the training split among samples where the rule fires (minimum 30 samples); (2) the words that most changed the model's score, measured by leave-one-word-out occlusion in log-odds. Indicators are independent checks, not an explanation of BERT's internal reasoning; the occlusion words are model-derived.

The original app's heuristic was ported to Python; on all 15,466 test rows the port and the original JavaScript agree (0 mismatches).

Backend tests: 63 passed in 8.90s; statement coverage of `backend/` 97.2% (lowest module 95.7%), against the NFR-09 target of 80%.

| bert-large, published model (E. Alvarado) † | 1.2% → 7.6% | 96.1% → 94.2% |

## 6. Limitations

- **Leakage handling.** Our models never saw the test set before final evaluation. The published model was evaluated on its own held-out test set, but its author used that set for checkpoint selection, so its scores are slightly optimistic. 68 test rows (0.44%) have a near-identical text in the training data.
- **Dataset source bias.** The URL-scheme artefact above; legitimate emails are largely Enron corporate mail and the SMS subset counts spam as phishing (label definition), so performance on today's phishing may differ. No out-of-distribution test set was evaluated (planned, not done).
- **English only.** The data and models are English; other languages were not tested.
- **Truncation.** BERT reads at most 512 tokens; only 8.6% of training HTML pages fit. Weakest sample type by F1: bert-base, fine-tuned (Kasim): html; bert-large, published model (E. Alvarado) †: html.
- **Single training run.** One seed; GPU training on Apple MPS is not bit-for-bit deterministic, so re-runs give close but not identical numbers. The best checkpoint was the last one evaluated, so longer training might help; this was not tested, to avoid tuning on the test set.
- **Scope versus the proposal.** Not implemented: user authentication and roles (FR-02, NFR-01), web-based model training (FR-04), TLS (NFR-02), immutable audit log (NFR-10), load testing (NFR-04 at 50 users), usability and accessibility studies (NFR-06, NFR-07), uptime monitoring (NFR-08), an OpenAPI specification file (part of NFR-12), and SHAP explanations (occlusion is used instead).
